## Security checks

- Application manifest: only Internet and microphone permissions; platform automatic backup disabled. The launcher activity is the sole exported component and does not consume arbitrary incoming file paths or commands.
- Imported photos/audio: private randomized destinations, bounded stream copies, bounded decoded dimensions, cleanup of partial files and canonical ownership checks before deletion.
- Restore: bounded ZIP expansion and entry counts, traversal/duplicate rejection, complete hashes, typed settings XML, schema and foreign-key checks, trigger/view rejection and rollback/restart coordination. Existing regression suites are retained and rerun.
- Network recitations/text: fixed HTTPS sources, default platform TLS validation, response size limits, cancellation handling, content sanity checks and temporary-file cleanup.
- No confirmed exploitable vulnerability was identified in these reviewed paths. This is a source and automated-test review, not a guarantee against every possible vulnerability.

## APK delivery controls

The signed review workflow runs only on the work branch and on explicit delivery requests. It checks out the exact commit with persisted Git credentials disabled, runs the full unit suite and lint, builds an optimized non-debuggable Release APK, and verifies the established publisher certificate, application ID and canonical version. It checks all 12 transport WebPs in the APK and records test totals, source commit and SHA-256.

Signing uses configured repository secrets, or the existing restricted publisher backup when all signing secrets are absent. Partial signing configuration is rejected. Private signing files remain inside the trusted runner and are removed after the job; only the APK, public certificate, build metadata and checksum may be delivered. Delivery uses a short-lived Actions artifact, with a private pre-release fallback if artifact quota is unavailable. No production release or main merge is performed.
